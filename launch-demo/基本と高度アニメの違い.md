# 基本アニメーションと高度UIアニメーションの違い・仕様・技術水準

## 1. 一言でいうと

- **基本アニメーション（Launch）**  
  「きちんと動く」レベル。読みやすさと軽さを優先した、控えめで安定した動き。
- **高度UIアニメーション（Core）**  
  「印象に残る・差がつく」レベル。スクロールや操作に合わせた、意図的に設計された演出。

---

## 2. 違い・差（何が違うか）

| 観点 | 基本アニメーション（Launch） | 高度UIアニメーション（Core） |
|------|------------------------------|------------------------------|
| **目的** | 情報がすっと入ってくる・離脱を減らす | ブランドや訴求を「伝える」・記憶に残す |
| **動きの種類** | 主に「表示される」動き（フェード、軽いスライド） | 表示＋「反応する」動き（方向・スタッガー・ホバー・パララックスなど） |
| **トリガー** | ほぼ「画面に入ったら1回」 | スクロール量・マウス位置・画面に入ったタイミングなどを組み合わせ可 |
| **ユーザー操作への反応** | ほぼなし（またはボタンの色変化程度） | ホバーで傾く・光る・数値が動くなど、操作に応じた反応あり |
| **実装の複雑さ** | シンプル（CSS transition + 少ないJS） | やや複雑（IntersectionObserver・イベント・計算・タイミング設計） |

---

## 3. 仕様の違い（何をやるか）

### 基本アニメーション（Launch で含まれる想定）

- **ページ読み込み時**
  - ヒーローなど、最初に見えるブロックのテキスト・CTAを、短い遅延で順にフェード＋軽い上方向スライドで表示。
- **スクロール時**
  - セクションやカードが画面に入ったら、**一括で** フェード＋軽い上方向スライドで表示（方向は「上から」のみ、スタッガーはなし or ごく短い）。
- **ホバー**
  - ボタン：色変化＋ごく軽い上方向のずれ（2px程度）。  
  - カード・リスト：ホバー時の浮きや影は**つけない**（静的な見た目）。
- **その他**
  - 数値のカウントアップ、パララックス、テキストの下線アニメ、左右・下からのスライドイン、見出しの下線伸びなどは**含めない**。
- **技術**
  - CSS: `opacity` + `transform: translateY()` + `transition`。  
  - JS: IntersectionObserver で「入ったら class 付与」程度。  
  - 1種類の動きで統一し、実装・保守が軽いようにする。

### 高度UIアニメーション（Core で追加する想定）

- **スクロール連動**
  - 要素ごとに**登場方向を変える**（左・中央・右・下など）。
  - **スタッガー**：0.1〜0.4秒程度ずらして順番に表示。
  - **パララックス**：スクロール量に応じて奥・手前の要素を違う速度で動かし、奥行き感を出す。
- **ホバー・インタラクション**
  - カード：マウス位置に応じた**3Dチルト**（傾き）、浮き上がり、影の変化。
  - ボタン：ホバーで**光の帯が流れる**、拡大、影の強調など。
- **その他の演出**
  - **数値のカウントアップ**：画面に入ったタイミングで 0 から目標値までアニメーション。
  - **テキスト**：下線が左から右に伸びる、見出しの下線が伸びるなど。
  - **背景**：ヒーローなどでグラデーションがゆっくり動くなどのループ演出。
- **技術**
  - CSS: `transform`（translate / scale / rotateX・Y）、`transition`、`@keyframes`、擬似要素でのマスクや光。
  - JS: IntersectionObserver、scroll イベント（throttle）、mousemove での座標計算、requestAnimationFrame でのカウントアップなど。
  - アクセシビリティ・パフォーマンス（`prefers-reduced-motion`、過度なアニメーションの抑制）を考慮した設計。

---

## 4. 技術水準の差

- **基本**
  - フロントエンドの一般的な知識で実装可能。  
  - ライブラリにほぼ依存せず、CSS と少ない JS で完結。  
  - ブラウザ負荷が小さく、低スペック端末でも崩れにくい。

- **高度**
  - スクロール・マウス・タイミングを「設計」する必要がある。  
  - パフォーマンス（60fps を意識した transform/opacity 中心）、アクセシビリティ、ブラウザ差の考慮が必要。  
  - デザインと実装のすり合わせ（何秒で、どの方向で、どのイージングで動かすか）の工数が増える。

---

## 5. 選び方の目安

- **まずは基本で十分な場合**  
  予算・スケジュールを抑えたい、情報を確実に届けたい、まずは「ちゃんとしたサイト」にしたい。
- **高度を検討する場合**  
  ブランドや差別化を強く出したい、LPや訴求ページで「印象」を重視したい、既存サイトが基本レベルで物足りないと感じている。
